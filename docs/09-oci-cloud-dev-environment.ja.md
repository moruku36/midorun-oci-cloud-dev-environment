# 09 OCI クラウド開発環境の設計：EC2 常駐構成を Always Free で再現する

[English](09-oci-cloud-dev-environment.md) | 日本語

みのるんの「Claude Code on EC2」構成（[05](05-claude-code-on-ec2.ja.md)、以下「原典」）を、OCI（Oracle Cloud Infrastructure）の Always Free 枠へ移植し、月額 ¥0 の個人用クラウド開発環境として構築する設計。

原典は EC2 t4g.large（2vCPU／8GB 級）に月 $52〜55 を払う構成。本設計では同じ型（常駐・自動復帰・インバウンド全閉じ）を無料枠で再現する。取り入れ方の全体像は [08 自分の環境への取り入れ方](08-takeaways.ja.md) を参照。

## 1. はじめに：目的と制約

目的は、開発の場をローカル Windows からクラウドへ移すこと。npm や TLS まわりの資材取得トラブルと、Windows Update の再起動で作業が止まる問題から開発を切り離す。

環境は個人用途の常駐箱とする。開発作業とエージェントの長時間セッションをここで回し、手元の端末はシンクライアントとして使う。

制約は「ずっと無料」。OCI の Always Free 枠と、契約済みの Claude Pro の範囲だけで運用し、API 課金は発生させない。

## 2. OCI 無料枠の実情とテナンシーの選択

Ampere A1（ARM）の無料枠は 2026-06-15 に半減した。Oracle 公式の Always Free ドキュメントでは、無料テナンシーは月 1,500 OCPU 時間＋9,000 GB 時間で、常時起動に換算すると 2 OCPU／12GB 相当になる。

従量課金（PAYG）テナンシーに上げると、無料枠は月 3,000 OCPU 時間／18,000 GB 時間（4 OCPU／24GB 相当）に戻り、枠内なら料金は発生しない。ただし枠外の利用がそのまま課金になるリスクを引き受ける。

推奨は、まず無料テナンシーで始めること。2 OCPU／12GB は原典の t4g.large（2vCPU／8GB）と同等以上で、不足が実測で出た場合にだけ、予算アラート付きの PAYG 化を検討する。

## 3. インスタンスの取り方

シェイプは VM.Standard.A1.Flex、イメージは Ubuntu の ARM64 版を使う。サイズは無料枠に収まる 2 OCPU／12GB を上限とする。

東京リージョンは A1 の容量が枯れがちで、作成が容量不足で弾かれることがある。時間帯を変えて根気よく再試行し、取れなければ大阪リージョンへ切り替える。

ブートボリュームは、無料のブロックストレージ枠（合計 200GB）に収める。原典が 30GB で足りているため、50GB 程度から始めて枠内に余裕を残す。

## 4. ベースセットアップ：原典構成の移植

OS は Ubuntu（ARM64）。初回セットアップはスクリプト化し、作り直し時も同じ手順で復元できるようにする。

常駐の仕組みは原典と同じにする。systemd ユニットが起動時に tmux セッション「claude」を自動生成し、ログイン時は .bashrc から既存セッションへ自動アタッチする。

セキュリティ更新は unattended-upgrades で自動適用する。ただし自動再起動は無効にし、再起動のタイミングは自分で選ぶ。Windows Update の問題をクラウド側で再現しないためである。

## 5. ネットワークとアクセス

インバウンドは全閉じにする。VCN のセキュリティリストに許可ルールを入れず、SSH の 22 番も開けない。

管理アクセスは Tailscale 経由に寄せる。SSH は tailnet 内からのみ、公開鍵認証のみで受け付ける。

Claude Code の Remote Control は外向き HTTPS 接続のみで動くため、この構成と競合しない。ポート開放なしで、スマホやブラウザからセッションへ入れる。

## 6. Claude Code の導入と Pro ログイン

Claude Code はネイティブインストーラで入れる。Linux ARM64 に対応しているため、A1 上でもそのまま動く。

認証は Claude Pro のサブスクリプションで行う。Remote Control は公式に Pro／Max／Team／Enterprise の claude.ai ログインが必須であり、API キーはサポートされない。環境変数に ANTHROPIC_API_KEY があると Remote Control がブロックされるため、「API キーを設定しない」ことが設計要件になる。これにより API 課金はゼロに保てる。

ヘッドレス環境でのログインは、CLI が表示する URL とコードを手元の端末で承認する方式で行う。常駐セッションでは、原典の設定（`remoteControlAtStartup: true`）と同様に、起動時から Remote Control を有効にする。

注意として、Pro の利用上限（5 時間枠と週間枠）はサーバー上でもそのまま適用される。長時間セッションを回す場合は、この上限が律速になる。

## 7. 無料を守る運用ルール

¥0 を維持するためのチェックリスト。

- [ ] インスタンスは A1 の無料枠（無料テナンシーなら 2 OCPU／12GB）に収める
- [ ] ブロックボリュームは合計 200GB 以内に収める
- [ ] 有料イメージや Marketplace の有料プランを選ばない
- [ ] アウトバウンド転送量を OCI コンソールで月 1 回確認する（無料枠の上限値は要確認）
- [ ] 無料テナンシーでも、実支出が発生したら通知されるよう支出アラートを設定する
- [ ] PAYG 化した場合のみ、予算アラートの設定を必須とする
- [ ] 使わないリソース（不要になったボリューム等）を残さない

## 8. 構築フェーズと受け入れチェック

構築の実行者はフワッチ（Muse、クラウド VM 上で稼働）が担い、クラウドからクラウドへ直接作業する。Windows 側エージェントは使わない。ローカル Windows には TLS／npm の資材取得トラブルがあり、ローカル経由の作業が止まる恐れがあるためである。

モルク本人の手が必要なのは 2 点だけ。OCI コンソールへのサインインと MFA 承認、およびインスタンスへ Claude Code を入れる際の Claude Pro（claude.ai）ログインの承認である。インスタンス作成、ベースセットアップ、Tailscale 導入、検証はすべてフワッチがクラウド側から行う。

| フェーズ | 内容 | 受け入れ条件 |
|---|---|---|
| 0 | テナンシー確認 | 無料テナンシーであること、ホームリージョン、カード登録済み（登録は完了済み）を確認 |
| 1 | インスタンス作成 | A1.Flex 2 OCPU／12GB、Ubuntu ARM64、ブートボリューム 50GB 程度で作成できる |
| 2 | ベースセットアップ | systemd＋tmux 自動生成、.bashrc 自動アタッチ、自動更新（自動再起動なし）が動き、再起動テストでセッションが復元される |
| 3 | Tailscale 導入 | インバウンド全閉じのまま、tailnet 経由で SSH できる |
| 4 | Claude Code＋Remote Control | Pro ログインで起動し、スマホから接続できる。ANTHROPIC_API_KEY が未設定であることも確認 |
| 5 | 実作業の移行 | 実際の開発リポジトリを 1 つ移し、資材取得とビルドがローカルの問題なく通る |

## 9. 注意点：限界と未確認事項

A1 の容量不足は最大の不確定要素で、東京で取れる保証はない。取得までの待ち時間は読めず、数日単位の粘りが必要になる場合がある。

ARM 前提のため、x86 前提のバイナリやツールチェーンの一部が動かない可能性がある。自分のツールチェーンが ARM64 で揃うか、事前確認が要る。

無料枠には、アイドル状態のインスタンスが回収対象になり得るリスクがある（OCI 公式ポリシー上の正確な条件は要確認）。対策は、箱を「本当に使う開発環境」として常時活用すること。

Pro の上限も限界の一つである。常駐セッションを回し続けると 5 時間枠・週間枠に当たるため、無制限の自律実行基盤にはならない。

## 10. まとめ

要点は 3 つ。原典の型（systemd＋tmux＋インバウンド全閉じ＋Remote Control）はそのままに、土台だけ OCI Always Free へ差し替えること。認証は Pro ログインのみとし、API 課金をゼロに保つこと。無料枠の数字（2 OCPU／12GB、200GB）を設計上限とし、拡大は PAYG 化の判断として分離すること。
