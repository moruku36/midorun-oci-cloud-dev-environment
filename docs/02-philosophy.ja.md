# 02 中核の考え方

[English](02-philosophy.md) | 日本語

登壇スライド・書籍・Qiita 代表記事から抽出した、みのるん式の中核概念。

## 1. 半自動化（全自動を目指さない）

- Claude Code はコーディング専用ではなく、経費精算・勤怠・出張手配などの日常雑務、案件対応（アジェンダ・議事整理・技術調査・資料作成）、社外講演の準備まで、**一部の工程でなく最初から最後まで**任せる。
- ただし全自動は目指さない。人間→AI→人間の流れで、**人間は要所の指示・承認だけ回す**。会議中も裏で3セッション並行で進行させる働き方を提示している。
- 実測感：一発で狙い通り仕上がるのは約6割（直近3か月の実測）、残りは往復で仕上げ、20回に1回は失敗。AI は自信満々に事実でない報告をすることがあるので、成果物は自分で開いて確認する。

## 2. 比喩：優秀な中途社員が3人、ただし入社初日

Claude は「総コン出身の優秀な中途社員が3人、専属アサインされた感じ。ただし入社初日で会社のことは何も知らない」。だからまず**オンボーディング**が要る：自分の役割・業務一覧・資料のありか・関係者を渡す。

### 準備3ステップ

1. **日常業務モノレポを作る**（仕事を1リポジトリに集約する）
2. **音声入力で自己紹介しまくる**（ツールURLや資料パスも全部渡し、フォルダ整備も丸投げする）
3. **あとは頼むだけ**

開始手段としては Claude Desktop アプリ＋月20ドルの Pro プランを推奨している。

## 3. モノレポと「コンテキストの複利」

- 仕事場（モノレポ）に手順・文面のこだわり・過去のやり取りが残ると、それが**別の仕事の質も上げる**。これが「コンテキストの複利」。楽になるのは2回目から。
- 例：経費精算では、手順を言わなくても過去のやり取りから自分で状況を調べ始める。
- 彼が Claude に編集させたファイルの8割以上は日本語の書類だった、という事実も示されている（＝コーディング以外の仕事が主戦場）。

## 4. プチ仕様駆動開発

コードを書かせる前に `/docs` に4ドキュメントを作る運用（Qiita 代表記事・デブサミ登壇より）。

| ファイル | 役割 |
|---|---|
| PLAN.md | 音声入力で10分ほど考えをダンプした計画（Aqua Voice を使用） |
| SPEC.md | 壁打ちで認識の齟齬を解消した仕様 |
| TODO.md | 進捗管理 |
| KNOWLEDGE.md | 学び・知見の蓄積 |

## 5. 頼み方

- 指示は**日本語の話し言葉でOK**。プロンプトの「呪文」は不要。
- 不明点は向こうから質問させる。
- **音声入力**（Aqua Voice が鉄板、OS標準でも可）でコンテキストの情報量を稼ぐ。
- 頼み方自体も「この仕事、どう任せたら楽になりますか？」と**設計ごと相談**する。
- 育て方は「**学習しといて**」の一言で設定に追記させる。設定が散らかったら「大掃除」を頼む。
- 毎晩22時のルーティンで全セッションを振り返らせ、学びの候補レポートを作らせる（直接書き換えは禁止、翌朝本人が確認して反映する）。

## 6. 承認と安全

- 標準の「自動モード」推奨。影響の大きい操作は別AIが裏で検査する前提。
- **分からない承認を「はい」で流さない**（拒否して聞き返す）。
- 安全装置（ガードレール）は自然文で AI 自身に設定を書かせる。例：「発注・送信・削除の確定ボタンは人間が押す」。
- 確認を絞る方がかえって安全、という指摘。
- セキュリティは「禁止と放任の間にある『制御』」＝攻めのセキュリティ。AI で増える論点は3つ：指示の入口（外部文章に紛れた指示）、操作の実行（自分の権限で手を動かす）、データの出口（LLM は社外）。
- 自身の失敗談：Slack 依頼対応中に返信が確認なしで送信された事故 → 「他の人へ届く操作は確認してから」と具体化したら再発しなくなった。
- セキュリティ部門には「どのデータをどこまで操作させるか」を具体的に書いて味方につける。

## 7. 接続できない環境への代替

- 社内システムに MCP で繋がなくても、ブラウザ操作で代替できる。**それもダメならコピペ用 Markdown（表）にまとめさせる**。それでも30分の仕事が5分になる。
- 「ログイン」「確定/送信」は必ず人間が実施するとルール化。
