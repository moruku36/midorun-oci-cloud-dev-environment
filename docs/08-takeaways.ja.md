# 08 自分の環境への取り入れ方

[English](08-takeaways.md) | 日本語

みのるん式を、筆者（moruku）の環境 —— 複数 AI エージェントの併用（Claude Code / Codex / Antigravity / Muse）、技術記事の執筆、個人開発 —— に引きつけた実践チェックリスト。優先順位順。

## すぐ効く（設定まわり）

- [ ] **正本を1か所に寄せる**：複数エージェントで同じルールを使うなら、共通ルールは AGENTS.md を正本にし、ツール固有の差分だけ各ツールの設定に置く（[03](03-settings.ja.md) の CLAUDE.md = `@AGENTS.md` ＋差分の型）。
- [ ] **スキル一覧のコンテキスト予算を絞る**：`skillListingBudgetFraction` のような上限を意識し、スキルが増えたら一覧が食う量を測る。
- [ ] **設定は dotfiles リポジトリへのシンボリックリンク**で同期し、コピー同期の工程をなくす。
- [ ] **調査系はサブエージェントに分離**し、親のコンテキストを守る。報告フォーマット（結論→問題→証拠→推奨対応）を固定する。

## 学習ループを回す

- [ ] **「学習しといて」を合言葉にする**：訂正・不満・作業の罠・確定した好みが出たターンは、その場で保存先ルーティング（共通→AGENTS.md／案件固有→そのリポジトリ／手順→スキル）に従って恒久化する。
- [ ] **恒久化は「自分で1回確かめた事実」だけ**。謝罪の代わりに設定を書き換えない。
- [ ] **夜間バッチは「提案まで」**：セッションの振り返りと学び候補レポートを作るところまで。反映は翌朝、人間が「採用」と言ってから（dreaming スキルの型）。
- [ ] **常時ロード量に上限を持つ**：AGENTS.md は「毎ターン・入口で要る判断」だけ。超えたらスキルへ移設する。

## 止めるべき所は hook で止める

- [ ] **機械で判定できるものだけ hook 化**する：宛先の誤り（check-outbound 型）、言語ドリフト（japanese-guard 型）。逆に学習のリマインドのような自然言語ルールは hook で毎ターン注入しない。
- [ ] hook の差し戻しは「1ターン1回まで」「対象箇所だけ直す」「言い訳を書かせない」まで設計する。
- [ ] 外部発信の**確認は1回だけ**に設計する（二重承認は形骸化する）。自分のリポジトリ宛ては素通り、他者宛てだけ止める。

## 仕事の進め方

- [ ] **半自動化を既定にする**：小さなタスクのスポット外注でなく、仕事を最初から最後まで任せて要所だけ承認する。
- [ ] **プチ仕様駆動開発**：コード前に PLAN.md（音声で10分ダンプ）／SPEC.md／TODO.md／KNOWLEDGE.md。
- [ ] **仕事場（モノレポ）にコンテキストを貯める**：手順・文面・こだわりを残し「コンテキストの複利」を効かせる。楽になるのは2回目から、と割り切る。
- [ ] **分からない承認は流さない**。拒否して聞き返す。ガードレールは自然文で書いて AI 自身に設定させる。
- [ ] 接続できない環境では **MCP → ブラウザ操作 → コピペ用 Markdown** の順に落とす。「ログイン」「確定/送信」は人間が押す。

## 常駐環境（クラウド開発への移行）

- [ ] みのるんの [EC2 常駐構成](05-claude-code-on-ec2.ja.md) は月 $52〜55 の有料構成。無料で同じ型をやるなら **OCI Always Free（Ampere A1、現行は 2 OCPU / 12GB 相当）** が候補：インバウンド全閉じ＋SSM 相当の管理接続＋ tmux 自動復帰＋ Remote Control（アウトバウンドのみ）の型はそのまま移植できる。
- [ ] ローカル Windows の資材取得トラブルや再起動から開発を切り離し、端末はシンクライアント化する。

## 書くこと・発表すること

- [ ] **ノウハウはスキルとして切り出す**（登壇資料スキルの例 → [07](07-articles.ja.md)）。実寸検査のような機械チェックまで含めてスキル化すると再利用性が上がる。
- [ ] 技術文書は「自分の手で start から end まで通す」まで「動きます」と書かない。情報源の信頼度ランキングを持ち、自分のナレッジも二次情報として疑う（tech-writing-verification の型）。
